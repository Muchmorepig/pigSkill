# 植物研究微信公众号文章整理

## 目标

把用户提供的科研素材整理为一篇可直接用于微信公众号排版的中文 Markdown 文章，并保存为：

```text
./<最终文章标题>.md
```

成稿不是论文摘要的简单拼接，而应是面向植物研究者的精选解读、方法观察和实验启发。

## 输入

素材可能来自：

- 植物研究周报、每日科研简报或论文清单
- 论文标题、摘要、DOI、期刊、预印本和原始链接
- 软件、数据库、分析工具或实验方法介绍
- 用户的研究笔记、个人评价和课题关联
- Markdown、TXT、PDF、DOCX、表格或多个文件
- 已有公众号文章或用户提供的风格样例

当任务依赖文件内容时，先完整读取相关文件。不要根据文件名、片段或未读取的页面猜测内容。

## 按需读取参考规范

根据任务读取本 Skill 目录中的参考文件：

- 周报、多研究合集、精简稿或扩展解读稿：读取 `references/article-structures.md`
- 撰写不同类型研究条目：读取 `references/research-entry-patterns.md`
- 处理语言、标题层级、术语和公众号排版：读取 `references/editorial-style.md`
- 保存前终检：读取 `references/quality-checklist.md`

不要把参考文件内容原样复制到成稿中。

## 核心原则

1. **不虚构。** 不编造论文、作者、期刊、DOI、日期、图号、样本量、数据、软件性能或链接。
2. **不改变研究含义。** 保留研究对象、实验条件、方法、统计结果、因果关系和局限。
3. **区分证据层级。** 明确区分论文结论、合理解释和编辑观察。
4. **问题导向。** 优先回答研究解决了什么问题、发现了什么、为什么重要、对实验或分析有什么启发。
5. **自然叙事。** 不要求每篇论文机械填写完全相同的栏目。
6. **有编辑取舍。** 重点研究写得更充分，补充性内容适当压缩。
7. **适合公众号阅读。** 使用短段落、清楚的小标题和有限的重点强调。
8. **保护专业名词。** 不随意改写物种名、基因编号、软件名、缩写和单位。
9. **优先使用自然中文正向陈述。** 减少用“不是……而是……”制造对比；只有确实需要排除误解或纠正错误前提时才使用。一般一篇文章最多出现 1 次，能直接陈述重点时不使用。

## 执行流程

### 1. 整理素材

识别并记录：

- 文章主题和覆盖时间
- 研究条目及其来源
- 正式论文、预印本、工具和补充资料的类型
- 重复信息与相互冲突的信息
- 用户明确强调的观点或课题关联
- 最值得优先精读的一项研究

同一研究出现多次时合并为一个条目。信息冲突时优先采用更直接、更完整的来源；无法确认时使用谨慎表达或标记待确认。

### 2. 确定文章模式

根据素材选择：

- **扩展解读型**：默认模式。适合信息充分、需要研究背景、机制解释和实验启发的周报。
- **精简周报型**：适合素材较少、用户要求简洁，或每项只有标题、链接和简短说明的情况。
- **专题文章型**：适合围绕一个共同科学问题整合多项研究，而不是逐篇排列。

具体结构见 `references/article-structures.md`。

### 3. 生成标题

标题优先级：

1. 用户明确指定的标题
2. 素材中已有的标题
3. 根据时间、主题和本期最重要趋势生成标题

标题要求：

- 准确概括内容
- 通常为 14–30 个中文字符
- 可使用中文全角竖线 `｜`
- 不使用“震撼”“炸裂”“颠覆一切”等标题党表达
- 除非证据充分，不使用“首次”“首个”“彻底解决”等绝对表述

正文默认不重复书写文章总标题；公众号标题栏和文件名承载总标题。

### 4. 先拟内部提纲

在内部确定：

- 前言写什么
- 速览顺序
- 每项研究的中文问题式标题
- 哪些研究需要二级或三级小节
- 是否加入“推荐优先精读研究”
- 是否加入“本周小结与实验启发”

不要把分析提纲或内部推理写入最终文章。

### 5. 撰写正文

默认先写前言和速览，再逐项展开。

每项研究通常覆盖：

- 背景或未解决问题
- 研究设计和关键方法
- 主要结果
- 具体重要性
- 可复用的方法或实验启发
- 必要的局限与证据边界

根据研究类型选择叙事结构，见 `references/research-entry-patterns.md`。

### 6. 处理用户课题关联

只有素材确实支持时，才加入用户自身课题或方法的关联分析。

论文未直接测试用户方法时，只能使用：

- “提供侧面支持”
- “与该设计逻辑一致”
- “提示”
- “可作为参考”

不得写成“证明该方法最好”或“直接验证该方法有效”。

### 7. 处理来源信息

每项研究可保留：

```markdown
**论文题目**：完整英文标题

**来源：**期刊或平台，日期

**DOI：**DOI

**原文链接：**原始链接
```

缺失字段可以省略，不得为了格式完整而编造。

默认不在文末重复建立参考文献列表；用户明确要求集中列出时再添加。

### 8. 保存文件

根据最终标题生成安全文件名，移除或替换：

```text
/ \ : * ? " < > |
```

中文全角符号可以保留。

使用 UTF-8 编码保存到当前工作目录：

```text
./<最终文章标题>.md
```

如果同名文件已经存在：

- 用户明确要求覆盖时覆盖
- 否则保存为 `<最终文章标题>-修订版.md`

文件只包含最终公众号正文，不包含分析过程、修改日志或任务说明。

### 9. 完成前检查

读取 `references/quality-checklist.md`，逐项检查事实、结构、语言、Markdown 和文件写入结果。

## 最终回复

完成后简要说明：

```text
微信公众号文章已整理完成，并保存为：<文件路径>
```

可以补充采用的文章模式，但不要在回复中重复粘贴全文，除非用户要求预览。
